**A1 Yango Tech Retail MCP** подключает AI-приложение к аккаунту ритейлера в Yango Tech Retail. Можно обычными словами проверять магазины, заказы, товары, цены и остатки, а при необходимости — создавать заказы и обновлять данные в аккаунте.

Сервер работает с B2B API продуктового ритейла и дарксторов. Это не кабинет продавца маркетплейса, не сервис такси и не Yango Delivery.

- **16 инструментов.** Девять инструментов чтения, пять инструментов записи и два потенциально разрушительных инструмента охватывают магазины, каталог, цены, остатки, заказы и чеки.
- **Безопасное начало с чтения.** Можно проверить связанные данные, ничего не меняя в аккаунте.
- **Понятные границы записи.** Создание и отмена заказов, обновление товаров, цен и остатков, а также создание скидок отделены от чтения.
- **Дополнительные методы API.** Технические специалисты могут вызывать методы без отдельного инструмента через `raw_request`.

Начните с запроса:

> Покажи наши магазины и остаток товара `[ID товара]` в каждом.

## Увидеть работу за минуту

> **Вы:** Покажи наши магазины и остаток товара `[ID товара]` в каждом.
>
> **Ассистент:** Покажу магазины, их идентификаторы и текущий остаток этого товара в каждом из них.
>
> **Вы:** Покажи цену этого товара во всех прайс-листах.
>
> **Ассистент:** Покажу прайс-листы и текущую цену товара в каждом. Данные в аккаунте не изменятся.
>
> **Вы:** В прайс-листе `[ID прайс-листа]` измени цену на `99.90`.
>
> **Ассистент:** Это изменит реальную цену для покупателей. Перед подтверждением покажу товар, прайс-лист, текущее и новое значение.
>
> **Вы:** Подтверждаю.
>
> **Ассистент:** Цена обновлена. Повторно прочитаю прайс-лист и покажу текущее значение.

> Магазины, товары, цены, остатки и статусы заказов всегда приходят из подключённого аккаунта ритейлера и актуального ответа API.

## Быстрый старт

Нужны Node.js 20+, аккаунт Yango Tech Retail и Bearer-токен ритейлера.

1. [Получите токен](#получение-доступа) у интеграционного менеджера Yango Tech.
2. Добавьте сервер в своё AI-приложение по одной из инструкций ниже.
3. Начните с запроса только на чтение:

   > Покажи наши магазины и остаток товара `[ID товара]` в каждом.

## Что можно поручить

### Проверить магазины и каталог

- Получить список магазинов с идентификаторами, статусом, координатами, адресом и названием, если они доступны.
- Просматривать товары по страницам и проверять их статус, категорию, локализованные названия, штрихкоды и дополнительные атрибуты.
- Создавать или обновлять до 100 товаров за один запрос. Запись с тем же идентификатором обновляет товар, а не создаёт дубликат.

### Проверить и обновить цены

- Получить список прайс-листов и прочитать цены товаров из одного или нескольких списков.
- Сравнить цену одного товара в разных прайс-листах.
- Установить до 100 цен за один запрос, передавая значения строкой, например `"150.00"`.
- Создать до 100 скидок для отдельных магазинов после уточнения структуры полей у Yango Tech.

### Проверить и обновить остатки

- Читать остатки по магазинам с идентификатором товара, количеством и типом полки.
- Обновить до 1000 строк остатков для одного магазина.
- Использовать `initialize` для первой загрузки остатков и `modify` для обычных обновлений.

### Работать с заказами и чеками

- Создать заказ после сбора магазина, товаров, количества, цен, условий доставки и способа оплаты.
- Получить данные заказа и одновременно проверить актуальное состояние нескольких заказов.
- Читать ленту событий: новые заказы, изменения состояния и выпуск чеков.
- Получить фискальный чек по идентификатору заказа или чека.
- Отменить заказ после проверки текущего состояния и причины отмены.

### Использовать дополнительные методы API

`raw_request` позволяет вызывать методы `/b2b/v1/*`, для которых пока нет отдельного инструмента: обновление заказов, НДС, связи магазинов с прайс-листами, сборка, логистика и 3PL-доставка. Такой запрос может изменить реальные данные, поэтому инструмент предназначен для технических специалистов, знакомых с исходным API.

Полные схемы, поля ответов и пробелы исходного API находятся в [справочнике инструментов](docs/TOOLS.md).

## Как связаны данные ритейла

| Сущность | Как используется |
|---|---|
| Магазин | Определяет точку, для которой читаются или меняются остатки и скидки |
| Товар | Один `product_id` связывает каталог, цены, остатки и позиции заказа |
| Прайс-лист | Хранит цены товаров отдельно от магазина; связь магазина с прайс-листом настраивается другим методом API |
| Строка остатка | Связывает товар, магазин, количество и тип полки; товарный остаток обычно использует тип `store` |
| Заказ | Использует заданный ритейлером `order_id`; данные заказа и его текущее состояние читаются отдельно |
| Чек | Получается по `order_id` или `receipt_id`, когда он доступен |

Каталог, прайс-листы и остатки читаются постранично по курсору. Если в ответе меньше записей, чем запрошено, текущая лента закончилась. Лента событий заказов непрерывная: сохраните последний курсор и позднее запросите следующую страницу.

## Что изменится в аккаунте

Сервер передаёт AI-клиенту MCP-аннотации чтения, записи и разрушительных действий. Когда и как запрашивать подтверждение, решает само AI-приложение.

| Действие | Результат | Изменяет аккаунт |
|---|---|---:|
| Читать магазины, товары, прайс-листы, цены, остатки, заказы или чеки | Возвращает актуальные данные аккаунта | Нет |
| Создавать или обновлять товары | Добавляет или перезаписывает реальные записи каталога | Да |
| Устанавливать цены | Перезаписывает цены для покупателей | Да |
| Создавать скидки | Добавляет реальные скидки для магазинов | Да |
| Обновлять или инициализировать остатки | Перезаписывает количество товара в магазине | Да |
| Создавать заказ | Добавляет реальный заказ с указанным `order_id` | Да |
| Отменять заказ | Переводит заказ в состояние отмены | Да |
| `raw_request` | Вызывает другой метод API, включая возможную запись | Зависит от метода |

Перед записью попросите ассистента показать магазин, товары, прайс-лист, количество, текущие и новые значения. Ответы операций записи не полностью документированы в исходном API, поэтому после успешного изменения цены или остатка сервер может повторно прочитать данные и показать актуальное значение.

## Получение доступа

Yango Tech выдаёт Bearer-токен для аккаунта ритейлера через интеграционного менеджера. В этом репозитории не описан самостоятельный портал для получения токена.

1. Обратитесь к интеграционному менеджеру Yango Tech и запросите Bearer-токен ритейлера.
2. Добавьте его в AI-клиент как `YANGO_RETAIL_TOKEN`.
3. Не добавляйте токен в Git и передавайте его только через секреты или переменные окружения AI-клиента.

Адрес производственного API — `https://api.retailtech.yango.com`. Все методы, включая чтение, используют POST с JSON-телом и находятся под `/b2b/v1/*`.

> Токен хранится в локальной конфигурации AI-клиента. Относитесь к нему как к паролю и не добавляйте конфигурацию с реальным токеном в Git.

## Настройка

| Переменная | Обязательна | По умолчанию | Что задаёт |
|---|---:|---|---|
| `YANGO_RETAIL_TOKEN` | да | — | Bearer-токен от Yango Tech; также поддерживается имя `YANGO_AUTH_TOKEN` |
| `YANGO_RETAIL_API_BASE_URL` | нет | `https://api.retailtech.yango.com` | Другой корневой адрес API; также поддерживаются `YANGO_API_BASE_URL` и `YANGO_DOMAIN` |
| `YANGO_RETAIL_TIMEOUT_MS` | нет | `60000` | Таймаут одного запроса, мс |
| `YANGO_RETAIL_MAX_RETRIES` | нет | `3` | Максимальное число повторов при временных ошибках; запись не повторяется после сетевой ошибки или ответа 5xx |
| `ASKADS_TELEMETRY` | нет | включена | `0`, `false`, `off` или `no` отключает анонимную телеметрию |

## Данные и телеметрия

### Запросы к Yango Tech Retail

Сервер запускается на вашей машине и передаёт данные ритейлера напрямую на настроенный хост API Yango Tech Retail. Bearer-токен добавляется только к запросам на этот хост. Даже `raw_request` принимает относительный путь и отклоняет путь, который ведёт на другой домен.

### Анонимная телеметрия

По умолчанию сервер отправляет на `usage.gistrec.cloud` технические события: запуск сервера, имя вызванного инструмента и фиксированный код причины неудачного запуска.

В события входят случайный идентификатор установки, версия пакета, имя и версия AI-клиента, версия Node.js и операционная система. **Bearer-токен, данные ритейлера, аргументы инструментов и тексты запросов не читаются и не отправляются.** Телеметрия ограничена таймаутом в две секунды и не блокирует вызовы инструментов.

Чтобы отключить телеметрию, добавьте:

```text
ASKADS_TELEMETRY=0
```

Реализация находится в [`src/telemetry.ts`](src/telemetry.ts).

## Ограничения и фоновая работа

- **Публичная квота API не описана.** Официальный Python-клиент придерживается пяти запросов в секунду для одной пары «токен + метод». Используйте это как рабочую рекомендацию, а не как опубликованный лимит API. Этот сервер не ограничивает заранее частоту каждого вызова.
- **Ответы 429 повторяются.** Сервер учитывает `Retry-After`, если он передан, и делает не больше числа повторов из `YANGO_RETAIL_MAX_RETRIES`.
- **Запись не повторяется после неопределённой ошибки.** Повторы после сетевой ошибки или ответа 5xx применяются только к операциям чтения. После неопределённого результата записи сначала прочитайте актуальный заказ, цену или остаток.
- **Действуют ограничения пакетов.** Товары, цены и скидки принимаются пакетами до 100 записей, остатки — до 1000 строк.
- **Фонового наблюдения нет.** Сервер работает только во время вызова из AI-приложения. Если приложение поддерживает задания по расписанию, оно может периодически проверять статусы заказов или остатки.
- **Автоматического отката нет.** Успешное обновление сразу изменяет аккаунт ритейлера.
- **Удаление ограничено исходным API.** Товары и цены обновляются с заменой; известных методов удаления товаров, цен и скидок нет.
- **Поддержка скидок в исходном API неполная.** Точные ключи периода действия и размера скидки не описаны, а известных методов чтения или удаления скидок нет. Перед использованием уточните формат у Yango Tech.
